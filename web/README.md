# C.U.T.Y — interactive engineering portfolio

Standalone frontend-only React / TypeScript / Vite application. Three.js, React Three Fiber and Drei render the actual assembly. Lucide supplies icons; responsive styling uses local CSS. The face uses pre-rendered assets generated by the robot's original Python renderer. No AI requests, backend, external fonts, analytics, camera access or robot connection.

## Run and verify

Requires Node.js 22.12+ (or a newer supported release) and npm. From the repository:

```sh
cd web
npm ci
npm run dev
```

Open Vite's printed URL (normally http://127.0.0.1:5173). On Windows use `npm.cmd` if PowerShell blocks `npm.ps1`. Dependencies are installed only in `web/node_modules`.

```sh
npm run lint
npm test
npm run build
npm run preview
```

`npm run test:e2e` runs the desktop and mobile-emulation browser suite. On this Windows machine it uses the existing Microsoft Edge executable; on other systems it uses Playwright Chromium. If Chromium is missing, install it inside the web project only: set `PLAYWRIGHT_BROWSERS_PATH` to `web/.browsers` (absolute path), then run `npx playwright install chromium`, and retain that environment variable when testing. Browser tests cover real GLB loading, view controls, EN/ES, component details, responsive overflow, reduced motion and the missing-model state. Generated screenshots/reports stay ignored under test-results/.

Build performs strict TypeScript checking and produces `web/dist/`. Preview serves that production build. Do not open index.html through file://.

## Real model

`hardware/cad/glb/CUTY_V17_Ensamble_completo.glb` is copied unchanged to **web/public/models/cuty.glb**, replacing V16. The loader uses Vite's base URL and a version query for cache invalidation, including subdirectory deployments. Missing/invalid models and WebGL failures display placement instructions and a reload control; the rest of the page remains accessible.

Measured V17 GLB: **110 meshes**, **116,741 triangles**, no authored materials, rig or animation clips. This CAD export uses millimeter coordinates and Z as vertical: source extents X 180 × Y 173.02 × Z 365. The viewer rotates a cloned instance −90° about X, making Y vertical, then uniformly fits it. Displayed assembly bounds are **X 180 × Y 365 × Z 173.02 mm**. Source geometry, part placement and GLB bytes are preserved. Front/side camera views are now +Z/+X in the oriented viewer, with the actual screen facing +Z. Parts are not articulated or individually selectable.

All non-screen surfaces receive the requested black material (`#101114`, roughness 0.52, metalness 0.25). Lights produce colored reflections, but the base material remains black. The display is mapped to the existing glass mesh `part_100`, identified by its source bounds (83.79 × 1.60 × 54.86 CAD units, front Y ≈ −47.45). Only its 54 front-facing planar triangles receive the face texture; its back/edges and all other parts remain black. UVs are generated in memory from the glass X/Z coordinates, preserving the face's 480:320 aspect ratio. This adds no floating screen plane and does not modify the source asset.

Drag / one-finger orbit, wheel / pinch zoom, presets, zoom buttons, reset, wireframe and optional autorotation work locally. Focus the viewer and press +, - or Home. Buttons are keyboard accessible. Autorotation starts off, respects reduced motion and pauses outside the viewport or in a hidden tab. One lazy canvas, demand rendering and capped DPR limit GPU load. There are no fake component hotspots. A future named, articulated GLB can add a per-part mapping in viewer/ without changing the hardware interface.

The face demo uses **the original robot renderer**, exported offline into four lossless WebP atlases (neutral, listening, happy, surprised). Eyes, colors, cheeks, mouth, aspect ratio and expression parameters come from `cuty.face.renderer.FaceRenderer`, the same class used by the touchscreen launcher. Each atlas contains nine gaze positions at four mouth levels plus blink frames, all at the original 480 × 320 resolution. The 3D LCD and face lab share expression, gaze, blink and synthetic mouth state through `FaceSimulationProvider`. The LCD controls below the viewer work locally; changing an expression in either location updates both. A 480 × 320 canvas texture uploads only the selected frame. Browser gaze is quantized to those positions; timing and mouth movement are a simulation, not live microphone-driven lip sync or robot control. Reduced motion stops the loop. No Python runs in the browser. Regenerate assets, without modifying robot files, using an existing Pillow environment:

```powershell
raspberry/.venv/Scripts/python.exe web/scripts/export-face.py
```

Run that export command from the repository root. Exported files under `web/public/face/` are included in normal static builds; users do not need Python to run the website.

## Structure and future integration

- `src/App.tsx`: page composition and contextual selectors.
- `src/components/Architecture.tsx`: interactive architecture.
- `src/viewer/`: lazy WebGL scene, camera rig, model measurement.
- `src/simulations/`: original face assets with explicitly labeled local playback.
- `src/state/`: EN/ES context, media-query state and shared offline face simulation.
- `src/data/project.ts`: typed bilingual content and evidence links.
- `src/communication/robot.ts`: offline transport interface.
- `src/App.test.tsx`: interaction and geometry-normalization tests.

English is initial. ES/EN changes page content and document language locally. Never add credentials to this frontend. Future Python/WebSocket code can implement RobotTransport; offline snapshot fields are null. Connection lifecycle, authentication and commands require a separate design. This release opens no sockets and fabricates no telemetry. Legacy dashboard/ and digital-twin/ notes are retained as historical placeholders; this Vite app is the current entry point.

## Static deployment

**Vercel:** Root Directory `web`, preset Vite, build `npm run build`, output `dist`. No API keys or environment variables.

**Netlify:** base `web`, build `npm run build`, publish `dist`. No functions or routing rewrites; navigation uses anchors.

**GitHub Pages:** build in web and upload `web/dist` with the standard Pages Actions workflow. Default relative base (`./`) resolves scripts and GLB under the project URL. For an explicit base set `BASE_PATH=/C.U.T.Y/` before building (PowerShell: `$env:BASE_PATH='/C.U.T.Y/'`). Select GitHub Actions as the Pages source and use configure-pages, upload-pages-artifact and deploy-pages in a separately configured workflow. No root workflow is added because this implementation is scoped to web/.

The Pi may be switched off. Offline distribution must include the complete dist directory, including models/cuty.glb.
